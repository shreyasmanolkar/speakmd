The 30-second mental model

Four choices make the whole system click.

Understand these constraints and the rest of SpeakMD becomes a predictable pipeline—not a black box.

Local by design

The document, job state, model, and generated audio remain on the user’s machine. There are no accounts, hosted APIs, or external databases.

One model owner

A single worker thread processes one job at a time. That prevents duplicate model loads, keeps RAM/VRAM predictable, and avoids GPU contention.

Filesystem as persistence

Each job is a directory. job.json is its source of truth, while atomic WAV checkpoints record completed synthesis work.

Structure becomes speech

The parser does not render Markdown to HTML. It turns headings, tables, links, lists, and code into language that still makes sense when heard.

✓ A useful analogy
  • An Express-like local HTTP server
  • A service layer plus one in-process worker
  • The filesystem acting as database and object storage
× What it is not
  • Not a cloud or multi-user service
  • Not a Redis/BullMQ-style async queue
  • Not a general-purpose Markdown renderer

Recovery, made visible
The system is designed around interruption.
Speech inference cannot be safely stopped mid-call. SpeakMD makes the boundaries around each call reliable instead.

        
Interruption lab

The atomic ordering is the reliability trick.
A chunk WAV is atomically written before job.json is updated. If the process dies between those writes, startup reconciliation detects the valid WAV and adopts it as completed.

        
Pause
Finish, save, stop
The current chunk is kept; resume starts at the first missing checkpoint.
Cancel
Discard in-flight only
Completed chunks stay on disk; audio still inside inference is dropped.
Retry
Redo failed work
Failed chunks return to pending, or final assembly runs again without valid audio being regenerated.
Restart
Reconcile, then continue
Interrupted jobs are re-queued and every checkpoint is validated before synthesis.

Hints are optional at runtime
x: str communicates intent, but this repository does not configure mypy or Pyright. from __future__ import annotations stores hints lazily; FastAPI only enforces annotations it explicitly inspects.

          
None, but no undefined
A missing dictionary key raises KeyError unless .get() is used. Also, empty [] and {} are falsy in Python—unlike JavaScript.

          
pytest injects fixtures by name
A test parameter named tmp_path or monkeypatch receives a built-in fixture. Plain assert replaces Jest’s expect API.

          
Text and bytes are distinct
Uploads arrive as bytes, decode with UTF-8, and are hashed as bytes. Python str is text. An f-string such as f"Chunk {index}" is the template-literal equivalent.

          
Job state is plain runtime data
dict, list, and set map roughly to object/Map, Array, and Set. json.loads parses; json.dump writes. Jobs use dictionaries rather than Pydantic models.

          
Environment reads are direct
os.environ.get("SPEAKMD_PORT", "8000") is the process.env bridge. There is no dotenv layer, and SPEAKMD_OUTPUT must be set before app.py is imported.

        


        

          
01What exactly gets stored for a job?
A stable directory is derived from the filename, source hash, and settings hash. It contains the source document, persisted state, independent WAV chunks, and final outputs.
input.mdThe UTF-8 source document
job.jsonSettings, chunks, attempts, timing, errors
chunks/0001.wavMono 24 kHz durable checkpoints

          
02Which dependencies are optional at runtime?
Kokoro and PyTorch run in-process; model files download from Hugging Face on first use. ffmpeg and nvidia-smi are external binaries. Missing ffmpeg means WAV-only completion; missing nvidia-smi means unavailable GPU metrics. CPU synthesis remains supported.

          
03How are duplicate uploads reused?
The ID combines a slug, the first 12 characters of the source SHA-256, and the first 8 characters of a settings hash. Uploading identical bytes with identical settings reopens the existing directory. Voice, speed, device, maximum characters, and chunking version all influence identity.

          
04What is covered by the documented test suite?
The deterministic tone renderer lets the documented tests cover narration fidelity, semantic chunk limits, table-row context, pause/resume, restart recovery, checkpoint reuse, and final audio construction without downloading model assets. HTTP routes, Kokoro itself, resource metrics, and several validation edges are not covered there.
